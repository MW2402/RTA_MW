 # Retail Shelf Stock-Out Early Warning System

## Overview

This project implements a Real-Time Analytics (RTA) solution for predicting retail shelf stock-out risk using Apache Kafka, FastAPI, and Online Machine Learning.

The system continuously generates inventory events, evaluates stock-out probability in real time, generates alerts for high-risk products, and incrementally updates the predictive model using online learning.

The project demonstrates:

- Apache Kafka event streaming
- Real-time event processing
- Machine Learning inference through FastAPI
- Incremental learning using `partial_fit()`
- Alert generation and monitoring
- Terminal-based dashboarding
- Live chart generation using Matplotlib
- Model versioning and snapshot management

---

## Business Problem

Retail stores lose sales whenever products become unavailable before replenishment arrives.

Traditional inventory monitoring is often batch-based and reactive. Managers discover stock shortages after they have already affected customers.

This system provides:

- Continuous inventory monitoring
- Real-time stock-out prediction
- Automatic alert generation
- Continuous model improvement

```text

    v

    |
    v
ml_consumer.py ----> ml_api.py
    |                    |
    |                    v
    |             Stock-out probability
    |
    +----> scored_inventory_events
    |
    +----> stockout_alerts
    |

                    |

                    |
```

## Synthetic Data Generation

The generator produces several inventory scenarios:

### Normal Cases

- High stock
- Low sales

### Clear Risk Cases

- Low stock
- High sales

### Low Stock / Low Sales

- Low stock
- Low demand

### Medium Stock / High Sales

- Medium stock
- Demand spike

### Low Stock With Replenishment

- Low stock
- Incoming replenishment

### Borderline Cases

- Moderate stock
- Moderate sales
- Uncertain outcome

These scenarios intentionally introduce ambiguity to improve model realism.

## Label Generation

### Initial Training

Labels are generated probabilistically.

Example concept:

```text
Risk score =
    stock component
  + sales component
  + replenishment component
```

Then:

```text
label = random() < probability
```

This avoids perfectly separable classes.

### Online Learning

The same probabilistic approach is used by `online_trainer.py`.

---

## Online Learning

### Process

1. `ml_consumer.py` generates online training events.
2. Events are buffered.
3. Every N events:
   - labels are generated
   - scaler is updated using `partial_fit()`
   - classifier is updated using `partial_fit()`
   - model bundle is saved
   - snapshot is created

### Automatic Model Reloading

`ml_api.py` automatically reloads the newest model bundle whenever the model file changes.

No API restart is required.

## Model Versioning and Snapshots

### Purpose

The system stores a snapshot after every online update.

Benefits:

- Model version tracking
- Rollback capability
- Offline analysis
- Demonstration of continuous learning
- Historical model comparison

### Snapshot Storage

```text
models/
└── snapshots/
```

Example:

```text
stockout_model_update_0001_YYYYMMDD_HHMMSS.pkl
stockout_model_update_0002_YYYYMMDD_HHMMSS.pkl
...
```

Each snapshot contains:

```python
{
    "scaler": scaler,
    "classifier": classifier,
    "model_name": "...",
    "feature_columns": [...],
    "last_update_number": N,
    "last_update_time": "..."
}
```
